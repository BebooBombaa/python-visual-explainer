## 🧠 قلب المشروع: `src/pythonParser.ts`

### لماذا مُحلّل ثابت وليس مُفسّراً حقيقياً؟

| | مُحلّل ثابت (الحالي) | مُفسّر حقيقي (Pyodide) |
| :--- | :--- | :--- |
| الحجم | ~0 KB إضافية | ~10 MB تحميل |
| السرعة | فوري | ثوانٍ للإقلاع |
| يعمل أوفلاين | ✅ فوراً | ⚠️ بعد التحميل |
| الدقة | تقريبية | كاملة 100% |
| مناسب لـ | **الشرح التعليمي** | التنفيذ الفعلي |

اخترنا المُحلّل الثابت لأن **الهدف تعليمي**: الطالب يريد أن يفهم *معنى* السطر، لا أن يشغّل برنامجاً معقّداً.
دعم Pyodide مخطّط له في خارطة الطريق كوضع اختياري.

### البنى الأساسية

```ts
interface CodeStep {
  line: number;            // رقم السطر في المحرر
  originalLine: string;    // نص السطر كما كتبه المستخدم
  explanationAr: string;   // 🇸🇦 الشرح العربي المعروض
  explanation: string;     // 🇬🇧 الشرح الإنجليزي (للترجمة مستقبلاً)
  stepType: StepType;      // نوع العملية → يحدّد الأيقونة واللون
  variables: VariableState[]; // لقطة (snapshot) لكل المتغيرات عند هذه الخطوة
  output?: string;         // ما سيُطبع (لأوامر print)
  executionOrder: number;  // ترتيب التنفيذ
  indent: number;          // مستوى الإزاحة (لفهم الكتل)
  conditionValue?: boolean;// نتيجة الشرط ✓/✗
  loopInfo?: {...};        // معلومات الحلقة (المتغير، المدى، التكرارات)
}
```

> 🔑 **مفهوم مهم:** كل خطوة تحمل **لقطة كاملة** لحالة المتغيرات في تلك اللحظة.
> هذا ما يجعل الشريط الزمني في `VariableWatch` ممكناً — نحن ببساطة نعرض `steps[i].variables`.

### ترتيب المطابقة مهم جداً ⚠️

الدوال تُطابق الأنماط **بالترتيب من الأخص إلى الأعم**:

```
1. سطر فارغ          8. else:
2. تعليق #           9. for
3. import           10. while
4. print()          11. try / except
5. def              12. الإسناد المركّب  (+=)  ← قبل الإسناد العادي!
6. return           13. الإسناد العادي   (=)
7. if / elif        14. المقارنة → 15. غير معروف ❓
```

**مثال على الخطأ الشائع:** لو وضعت نمط الإسناد العادي `(\w+)\s*=\s*(.+)` قبل الإسناد المركّب،
فإن السطر `x += 5` سيُطابق خطأً ويُفسَّر كأنه `x = (+ 5)`. لذلك الترتيب حرج.

### دوال المساعدة الداخلية

| الدالة | الوظيفة |
| :--- | :--- |
| `evaluateExpression()` | تقييم تعبير → قيمة نصية (يدعم النصوص، الأرقام، f-string، العمليات) |
| `evaluateCondition()` | تقييم شرط → `true` / `false` (يحوّل `and/or/not` إلى `&&/\|\|/!`) |
| `evaluateFString()` | استبدال `{name}` بقيمة المتغير داخل f-string |
| `inferType()` | استنتاج نوع البيانات من شكل التعبير |
| `getTypeArabic()` | ترجمة اسم النوع للعربية (`int` → عدد صحيح) |
| `getVarArray()` | تحويل خريطة المتغيرات إلى مصفوفة لقطة |

> 🔒 **ملاحظة أمان:** التقييم يستخدم `Function()` على تعبيرات بسيطة **بعد استبدال أسماء المتغيرات بقيمها**،
> ومحاطة بـ `try/catch`. الكود يعمل بالكامل في متصفح المستخدم ولا يُرسل لأي خادم.

## ➕ كيف تضيف دعماً لأمر بايثون جديد؟

سنضيف كمثال دعم أمر `break`:

### الخطوة 1 — أضف النوع

في `src/pythonParser.ts` داخل `interface CodeStep`:

```ts
stepType: | 'assignment' | 'print' /* ... */ | 'break';   // ← أضف هنا
```

### الخطوة 2 — أضف قاعدة المطابقة

داخل حلقة `for` في `analyzePythonCode`، **قبل** الحالة العامة `unknown`:

```ts
if (line === 'break') {
  executionOrder++;
  steps.push({
    line: i + 1,
    originalLine: rawLine,
    explanation: 'Break — exit the loop immediately',
    explanationAr: 'كسر الحلقة — الخروج منها فوراً وتجاهل باقي التكرارات',
    stepType: 'break',
    variables: getVarArray(variables),
    executionOrder,
    indent,
  });
  continue;   // ⚠️ لا تنسَ continue!
}
```

### الخطوة 3 — أضف الأيقونة في بطاقات الشرح

في `src/components/StepVisualizer.tsx` داخل `stepIcons`:

```ts
break: { icon: '🛑', bg: 'bg-rose-900/20', border: 'border-rose-700/30', label: 'كسر' },
```

### الخطوة 4 — أضف الأيقونة في خريطة التنفيذ

في `src/components/FlowOverview.tsx` داخل `flowIcons`:

```ts
break: { icon: '🛑', color: 'bg-rose-500', labelAr: 'كسر' },
```

✅ **انتهيت.** شغّل `npm run dev` وجرّب كتابة `break` داخل حلقة.

## 🧱 المكوّنات

| المكوّن | المسؤولية | المدخلات |
| :--- | :--- | :--- |
| `App.tsx` | التخطيط، التبويبات، تشغيل التحليل | — |
| `CodeEditor` | إدخال الكود، أرقام الأسطر، دعم Tab | `code`, `onChange` |

هذا يعني أنك تستطيع استبدال المُحلّل بالكامل (مثلاً بـ Pyodide) دون لمس أي مكوّن، طالما أنه يُرجع نفس شكل `AnalysisResult`.

## 🔮 خطة دعم Pyodide (مستقبلاً)

الطريقة المقترحة للحفاظ على المعمارية النظيفة:

```ts
// src/engines/types.ts
interface PythonEngine {
  analyze(code: string): Promise<AnalysisResult>;
}

// src/engines/staticEngine.ts   ← المُحلّل الحالي (سريع، افتراضي)
// src/engines/pyodideEngine.ts  ← تنفيذ حقيقي (اختياري، يُحمّل عند الطلب)
```

ثم مبدّل في الواجهة: **⚡ وضع سريع** / **🐍 وضع دقيق**.
بهذا الشكل يبقى الموقع خفيفاً للمبتدئين ودقيقاً للمتقدمين.

## 🌍 خطة دعم تعدد اللغات

الحقول جاهزة بالفعل: كل خطوة تحمل `explanation` (إنجليزي) و `explanationAr` (عربي).
كل المطلوب مستقبلاً:

1. سياق React بسيط `LanguageContext` بقيمة `'ar' | 'en'`
2. دالة `t(step)` تختار الحقل المناسب
3. تبديل `dir="rtl"` / `dir="ltr"` على العنصر الجذر
4. ملف `src/i18n/` لنصوص الواجهة الثابتة
